# 8D 智能报告生成 — 3 分钟演示脚本

> 场景：非正式演示（质量部/科研处关键人）· 演示数据全部手造脱敏，不涉及任何真实型号/批次。
> 生成耗时约 3 分钟（本地模型），脚本按"边生成边讲解"编排，全程无冷场。

## 演示前准备（开场前 5 分钟）

```bash
# 1. 确认三个本地服务在线（全程无外网依赖）
curl -s http://localhost:11434/api/tags           # Ollama: qwen3.8:27b
curl -s http://localhost:8080/api/knowledge/list  # ka 应用: 3 份案例在库
# 2. 预热：发起一条生成，讲解环境时它在后台跑
curl -s -X POST http://localhost:8080/api/agent/8d/generate \
  -H "Content-Type: application/json" --data-binary @docs/demo-8d/records/QR-2026-1003.json \
  -o /tmp/resp-warmup.json &
```

## 0:00–0:30 开场（一句话定位）

> "质量异常记录进去，一份符合 8D 方法论的军工格式分析报告初稿出来——
> 检索、生成、排版，**全程跑在这台电脑上，拔了网线照样跑**。"

（展示一张拓扑：MES 导出记录 → ka 知识助手（RAG 检索历史案例 + 本地大模型生成）→ Word 初稿）

## 0:30–1:10 环境与"离线"卖点

- 打开任务管理器/Ollama 列表：qwen3.8:27b（17GB，本地推理）
- `env | grep -c ZHIPU` → 当前进程**没有云端 API key**（`SPRING_AI_MODEL_CHAT=ollama`）
- 强调三点：
  1. **数据不出网** — 异常记录、历史案例全在本地 Redis/内存，适合涉密环境；
  2. **知识库沉淀** — 3 份历史 8D 案例已向量化入库，检索命中 5 段作为分析参照；
  3. **工程师仍握决定权** — 输出是"初稿"，根因结论标注（待确认），由质量工程师审定。
